# BreakTheWall workflow adapter

This repository uses the `project-workflow` skills for research → plan → review → approve → implement → verify → archive. Every workflow skill reads this adapter and the plugin's shared workflow contract. Keep this adapter specific to this repository.

## Repository constraints

- Product identity (revised by the owner on 2026-11-05): BreakTheWall takes a source apart into source-linked parts and lets the learner explore how it holds together. **Exploration is the core**: the app reads the source's structure (parts, links with a declared or interpreted basis, the source's own questions), chooses the way in from that shape, and shows one view with three roles (guide, structure, source) on one shared state. Run (putting a link under load) and reassemble are later additions, not the current loop. It is not a course, chatbot, summarizer, memorization or gamified study app; review is opt-in. One loop for every subject: never choose the way in from a genre or a subject, and never add subject-specific modes. Never connect what the source does not connect. Judge new features against this. Source: [product definition](docs/product.md#identity).
- Product boundary: BreakTheWall supports general subjects as well as code. Sources may be user supplied or retrieved with AI assistance. Preserve this distinction when designing contracts and UI. Source: [product definition](docs/product.md).
- Current owners: `src/core` owns shell-independent lesson validation/state (including, from plan P-20261105-exploration, the structure contract, the detector, the source index and the reading report), `src/fixtures` owns original prepared content, `src/renderer` owns React UI, `src/desktop` owns Electron access, and `src/mcp` owns the MCP server for AI assistants (Node only, no Electron or React). Documentation lives under `docs/`; workflow evidence lives under `docs/workflow/`.
- Build and test runners: npm with `package-lock.json`. Use `npm run check` for TypeScript and Vitest, `npm run build` for production bundles, `npm start` for the local production desktop, and `npm run dev` for development. See [development](docs/development.md).
- Technical direction: TypeScript/React and Electron are established in T1. Exact versions are pinned in `package.json`; domain code must remain independent of React/Electron. `npm run package` builds an ad-hoc signed DMG for Apple Silicon (plan P-20261027-macos-dmg) and `npm run package:win` an unsigned Squirrel setup for Windows x64 (plan P-20261027-windows-alpha); CI checks both systems. `src/mcp` is a hand-written MCP server for Claude Desktop and Claude Code (plan P-20261028-mcp-integration). It reaches the app only through the local entry point in `src/desktop/incoming.ts`, which is off unless the learner turns it on. There is no Developer ID or Windows code signing, notarization or updater.
- External dependencies: no credentials or AI services are configured by this foundation. Provider documentation review is not proof of account access or a successful inference. Source: [foundation evidence](docs/workflow/research/R-20261021-foundation.md).
- Generated file: `STATUS.md` is derived from plan front matter by the project-workflow status generator. Edit the plan, then regenerate status.

- Publication boundary: the remote repository is public. Use original or suitably licensed fixtures. Earlier private code excerpts and local source snapshots are outside this repository's content scope. Source: [README](README.md) and foundation evidence.
