# A snapshot is the working copy, identified by content

When the learner opens a local folder, the source is its **working copy**: the files as they are on disk, tracked and untracked, minus what the project itself ignores. A git commit is only a label, because the learner reads the code in front of them, uncommitted changes included (R-20261025, finding 5). The snapshot is identified by a hash of its sorted (path, file `sha256`) pairs, so two readings share an overview only when every file is the same. A folder without git opens the same way: a folder of chapters is a large source too. (Owner, 2026-11-18, ticket "What is a repository snapshot: which files enter it, and how is it identified?".)

## Decision

- **Which files.** In git, tracked plus untracked files that are not ignored (`git ls-files -co --exclude-standard`). Ignored files never enter, not even the bill of materials; "How it was read" only counts them. Without git, any `.gitignore` present applies, and otherwise only `.git/` and `node_modules/` are left out.
- **Listed, not read**, each with its reason, recognised only by content or by declared signals, never by a folder's name: binary (control bytes), lock files named by their tools, generated (`linguist-generated`, `@generated`, `DO NOT EDIT`, `<auto-generated>`), vendored (`linguist-vendored`), minified (a line over `maxLineChars`), not UTF-8, symlinks (never followed), submodules (listed with their commit, opened as a source of their own).
- **Secrets.** Flagged lines are left out of the reading and appear as "secret, not read"; a whole-file rule (a private key, a keystore) leaves the whole file out. In the first version the learner cannot override an exclusion. Only the snapshot is scanned: git history is never read, so it never leaves the device.
- **Identity and label.** The content hash is the identity. The label in "How it was read" is "commit `abc1234` + 3 modified files", or "folder without git, read on <date>", or "git not available".
- **Git access.** The system `git`, when present, checked without starting an installer (on macOS `/usr/bin/git` opens the Command Line Tools dialog). Without it the folder opens as a folder without git; only the label loses its commit.
- **What is saved.** The text of the files actually read (the focus and the overview's digest) with their hashes and the snapshot's identity, never the whole repository. A saved exploration reopens without the folder. A new reading recomputes the identity; when it differs, the saved overview is stale and the app says so.

## Considered options

- **`HEAD` only.** Rejected: it explains code that differs from what the learner sees.
- **Commit plus the list of modified files as identity.** Rejected: a file changed twice without a commit keeps the same identity.
- **Leaving out a whole file when it holds a secret** (as R-20261025 suggested). Rejected: one line would hide a whole configuration file.
- **Letting the learner override a secret exclusion.** Deferred: a false positive costs a line, a false negative sends a key to a hosted model.
- **A longer default ignore list** (`dist/`, `build/`, `vendor/`, `.venv/`). Rejected: it guesses from names, and `vendor/` is real code in Go.
- **`isomorphic-git`.** Rejected: a dependency that would only serve a label.
- **Saving a pointer to the folder.** Rejected: citations would break at the first edit.
